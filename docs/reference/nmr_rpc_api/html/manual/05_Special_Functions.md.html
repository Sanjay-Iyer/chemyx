Special Functions

There are a few special functions that can be defined:

  • cleanup()
  • estimatedDuration()
  • save(fileName)

In general, the special functions should be at the start of the script, immediately after the configuration section.

Cleanup

The cleanup() function is called when the experiment is finished, whether it completed successfully, or it was canceled.

Most experiments will not need this, but occasionally, you may want to back up a setting at the start of the experiment and restore it at the end. For example, if the experiment changes integration regions, it may not be desirable to keep them after the experiment is finished.

function cleanup()
    -- Restore configuration
end

Estimated Duration

The estimatedDuration() function is called when the GUI asks for an estimate of how long the experiment will take. This is called when acquisition parameters are changed.

Here is an example for an experiment that does a multi-transient 1D acquisition:

function estimatedDuration()
    local timePerScan = core:totalScanTime()
    local totalTime = core:numScans() * timePerScan
    return totalTime
end

Save

The save() function is called when the Save button is clicked.

See the Save button example.

Transient Callback

The transientCallback() function is called after each transient (acquisition queue mode) or after transients number 1, 4, 8, etc. (acquire() mode.) It is only called if setCalculateIntermediateResults(true) is called first.

It is OK to do minimal processing and updating the display in this function. Processing and displaying 2D data will likely delay subsequent acquisitions.

function transientCallback(transientNumber, totalTransients)
    updateDisplay(dataSet1D)
end
