restructuring. Evidence came from file contents, repository-wide import and path
searches, `git ls-files`, `git log --all --name-status`, current documentation,
tests, and result manifests. Generated bytecode and cache files are inventoried

## Immediate findings

- `scripts/01_first_real_chemyx_nmr.py` is a ten-line wrapper. It imports
  `main` directly from `scripts/first_real_test.py`; therefore the legacy file
  is still the complete workflow implementation and cannot yet be archived.
- Workflow 01 directly uses `chemyx_lab.config`, `chemyx_lab.pump`,
  `chemyx_lab.nmr_rpc`, and `chemyx_lab.nmr`. It does not use the valve modules,
  `chemyx_lab.workflow`, any root compatibility module, or `deploy/`.
- `deploy/infuse_withdraw.py` is not imported or called anywhere. It is an
  earlier, standalone, pump-only bench script. It directly opens pyserial,
  writes ASCII plus `\r`, waits 0.2 seconds before `read_all()`, performs an
  infuse-first fixed-time sequence, and sends unprefixed `stop` commands. Those
  details make it historical command evidence, not reusable active code.
- `scripts/real_framework.py` and `scripts/sop_mock_workflow.py` contain unique
  workflow behavior. They are not safe to classify from names alone and remain
  explicit user decisions.
- Six legacy JSON files remain mixed into `configs/`. Four duplicate the new
  experiment/machine split, one belongs to the uncertain framework, and one is
  a tracked work-laptop configuration with concrete COM/IP values.
- The root compatibility modules exist only for the old `main.py` and legacy
  test imports. Active workflow 01 imports the package directly.

## Special investigation: deploy

`deploy/` contains exactly one file: `deploy/infuse_withdraw.py`.

1. It is not imported or called by `scripts/01_first_real_chemyx_nmr.py`.
2. It is not imported or called by `scripts/first_real_test.py`.
3. It contains unique historical details: direct pyserial construction, buffer
   resets before each command, ASCII + CR framing, a 0.2-second response delay,
   `read_all()`, fixed ten-second motion windows, infuse-before-withdraw order,
   and unprefixed `stop` commands.
4. It is a standalone legacy bench/deployment script, not an internal library.
5. It does not load a config file. It reads only `CHEMYX_PORT`; every other
   parameter is a literal.
6. Its transport and most commands overlap `chemyx_lab/pump.py`, but its direct
   read strategy, fixed timing, sequence direction, and unprefixed stop differ.
7. Proposed disposition: archive it as command-history evidence after checksum
   capture. It should not become a numbered workflow because workflow 01 is the
   supported integrated flow; it should not move into the package because the
   reusable behavior already exists there; and it is less safe and less
   configurable than the package-backed pump diagnostic.

After the approved move, the vague `deploy/` directory should be removed once
empty. No other deployment-related file exists.
