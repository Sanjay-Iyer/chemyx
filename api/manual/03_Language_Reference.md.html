Language reference

The Experiment Designer uses the Lua 5.1 interpreter.

You can create your own modules if you would like to share functionality between multiple experiments.

Available Lua libraries

The available libraries are:

  • table
  • string
  • math
  • debug
  • package

The "io" and "os" libraries are not available.

When do I use a colon and when do I use a dot?

Most access to the NMReady software is through objects. To call methods on an object, you use a single colon.

pulse90 = core:channelConfigSignal():get90PulseSeconds()

An exception to this is tables of constants. These are accessed using a dot.

decouplingSettings:setDecouplingModeSelection(DecouplingMode.On)

Other Lua functionality is provided by the Lua libraries. To access a function from one of the libraries, use a dot.

s = string.format("Linewidth: %.2f", linewidth)

Making copies of complex objects

In Lua, objects are referenced by a handle. When you use the assignment operator (=) to give an object a new name, it does not copy the object. The object just has two different variable names that refer to it. For example, this will result in one DataSet1D object that has two names, "original" and "notACopy":

original = core:dataSetSignal()
notACopy = original

Anything done to original after this still affects notACopy. To create a copy, either the set() or clone() method must be used on that object. Some objects support one or the other, so check the documentation first. Using DataSet1D as an example:

original = core:dataSetSignal()
copy = newDataSet1D("My copy")
copy:set(original)

Now operations can be performed on "original" or "copy" and they will not interfere with each other. This results in additional memory usage.

Long running experiments and memory usage

If you are collecting a lot of data into a Results2D, you will eventually run out of memory to store the data. Try to limit the number of points and reduce 1D zero filling. You will also be able to acquire much more data if it is not displayed in the GUI.

If you are running an experiment where many DataSet1D or Results2D are exported, consider deleting the data from memory after they are exported to disk. collectgarbage can be used to force memory to be freed for objects that no longer have a reference.

-- After export, the data is no longer required to be in memory.
exportResults2D(myResults2D, "my_experiment_results_1")
-- Remove the reference to the object:
myResults2D = nil
-- The object will be deleted here, allowing much more data to be
-- collected before the experiment is finished.
collectgarbage()
